# DRI Task Manager

DRI（Directly Responsible Individual = 直接責任者）を適切に設定したタスク管理を支援するスキルです。組織の成長に伴う責任の曖昧さを解消し、意思決定を迅速化します。

## DRIとは

- **1つのタスクに対して、1人の責任者を明確にする仕組み**
- DRIは最終決定権を持ち、結果に責任を負う
- 相談役（Consulted）は複数でOK、ただし決定権はDRIのみ
- 質問・報告・エスカレーションはDRIに一本化

### 解決する課題

- 「これ誰に聞けばいいんだっけ？」→ たらい回し
- 「みんなで決めよう」→ いつまでも決まらない
- 「誰が責任者？」→ 誰も名乗り出ない

## 役割定義

| 役割 | 意味 | 人数 |
|------|------|------|
| **DRI** | 最終決定権を持ち、結果に責任を負う | 1名のみ |
| **相談役** | アドバイス・レビューを行う（決定権なし） | 複数可 |
| **共有先** | 状況を把握しておく必要がある人（アクション不要） | 複数可 |

## 出力フォーマット（DRIマトリクス）

タスクを作成・整理する際は、必ず以下のマトリクス形式で出力してください：

```
タスク                        DRI   相談役          共有先        期限    状態
─────────────────────────────────────────────────────────────────────────────
リポジトリ構成決定              YAN   kodama, 天培   kodama        02/07   ✅完了
ベンダー権限設定                YAN   天培           kodama        02/10   🟡進行中
ブランチ運用ルール策定           YAN   kodama        天培, 橋本    02/14   ⚪未着手
```

### 状態の表記

| 記号 | 意味 |
|------|------|
| ⚪ | 未着手 |
| 🟡 | 進行中 |
| 🔴 | ブロック中（理由を併記） |
| ✅ | 完了 |

## タスク作成の流れ（対話型）

タスク作成は会話を通じて段階的に進めます。一度に全部決めません。

```
ステップ1: タスクの洗い出し
  ユーザーと会話しながらタスクを特定する
  「過不足ないですか？」と確認する
  ↓
ステップ2: DRI・期限・状態を決める
  各タスクにDRIを1名設定し、期限と状態を確定する
  NotionのPosition情報を参考にDRIを提案する
  （相談役・共有先は空欄のまま出力してOK）
  ↓
ステップ3: 粒度の確認
  タスクが大きすぎる場合は親子タスクに分割する
  完了まで2週間以上の場合は分割を提案する
  ↓
ステップ4: 相談役・共有先を決める（後日でもOK）
  Notion・Slackのやり取り履歴を参考に提案する
  「後で決めましょう」でも進める
```

## 親子タスクの分割

タスクが大きすぎる場合、親子タスクに分割します：

**分割が必要な目安：**
- 完了まで2週間以上かかる
- 成果物が複数ある
- 複数の領域にまたがる

**親子タスクの例：**

```
親タスク                       DRI    期限    状態
──────────────────────────────────────────────────
認証基盤の刷新                  中村   06/30   🟡進行中

  └ 子タスク                   DRI    期限    状態
    ──────────────────────────────────────────────
    認証方式の技術選定           中村   03/15   ⚪未着手
    認証フロー設計・実装         伊藤   04/30   ⚪未着手
    既存ユーザー移行             加藤   05/15   ⚪未着手
    E2Eテスト整備               渡辺   05/31   ⚪未着手
    本番切り替え                中村   06/30   ⚪未着手
```

**親子タスクのルール：**
- 親タスクにもDRIを設定する（プロジェクト全体の完遂に責任を持つ）
- 子タスクのDRIは親と別でもいい（各子タスクに最適な人をDRIにする）
- 親タスクの期限 ≧ 全子タスクの期限
- 親タスクの状態は子タスクから自動判定

## DRIの判断基準

DRIを誰にすべきかわからない場合、以下の順で判断してください：

1. **そのタスクを一番よく知っている人は誰か**
2. **その人は決定を下せる立場か**
3. **その人は今の業務量的に引き受けられるか**（同時DRI上限3つ推奨）

## バリデーションルール

### 必須（満たさなければ出力しない）

- ✅ DRIが1名だけ設定されている
- ✅ DRIはNotionに登録された個人名（チーム名やグループ名は不可）
- ✅ 期限が設定されている

### 警告（出力はするが注意を促す）

- ⚠️ 同一人物がDRIとして4つ以上のタスクに入っている → 過負荷の恐れあり
- ⚠️ 状態が🔴ブロック中なのに理由がない → 理由の記入を促す
- ⚠️ タスクの完了見込みが2週間以上 → 子タスクへの分割を提案する

## エージェントの振る舞いガイドライン

### やること ✅

- タスクの洗い出しではユーザーに「過不足ないですか？」と確認する
- DRIの設定ではNotionのPosition情報を参考に提案する
- 大きすぎるタスクには分割を提案する
- 相談役・共有先は「後で決めましょう」でも進める

### やらないこと ❌

- 一度に全部決めようとしない（段階的に進める）
- DRIをエージェントが勝手に決めない（必ずユーザーに確認する）
- 相談役がいないからといってタスク作成を止めない（後から追加できる）

## メンバー情報の参照

NotionのメンバーページからLangGeniusのメンバーを参照します。

**利用可能なフィールド：**
- **Name** - DRI・相談役・共有先のアサインに使用
- **Position** - タスク領域に適した人の判断に使用

## 相談役・共有先のアサイン方法

1. タスク作成時点ではDRI・期限・状態のみ確定
2. 相談役・共有先は後から決定する
3. NotionとSlackのやり取り履歴から判断する
4. エージェントが提案し、ユーザーが確認・修正して確定する

## DRIが決定を覆された場合

上位者がDRIの決定を覆す場合、**上位者が新しいDRIになる**。決定権を取るなら、責任も取る。

## 使用例

### 例1: 新しいタスクを作成する

**ユーザー:** 「新しいプロジェクトでタスクを整理したい」

**エージェント:**
1. 「どのようなタスクがありますか？」と質問
2. タスクリストを作成
3. 「過不足ないですか？」と確認
4. 各タスクのDRIを提案（Notion Positionを参考）
5. ユーザーと確認しながらDRI・期限・状態を確定
6. DRIマトリクス形式で出力

### 例2: 既存のタスクに相談役を追加する

**ユーザー:** 「このタスクに相談役を追加したい」

**エージェント:**
1. Notion・Slackの履歴を確認
2. 適切な相談役を提案
3. ユーザーと確認して確定
4. 更新されたDRIマトリクスを出力

### 例3: 大きなタスクを分割する

**ユーザー:** 「このタスクが大きすぎる」

**エージェント:**
1. タスクを分析
2. 子タスクへの分割を提案
3. 各子タスクのDRIを提案
4. 親子タスク構造で出力

## トラブルシューティング

### DRIが複数人になってしまう

❌ **間違い:** 「山田, 鈴木」のように複数人を設定

✅ **正しい:** どちらか1人に絞る。もう1人は相談役にする

### チーム名をDRIに設定してしまう

❌ **間違い:** 「開発チーム」「マーケティング」をDRIに設定

✅ **正しい:** チームの中から1人の個人を特定してDRIに設定

### 期限が設定されていない

❌ **間違い:** 期限欄が空白

✅ **正しい:** 暫定でも期限を設定する（後で変更可能）
